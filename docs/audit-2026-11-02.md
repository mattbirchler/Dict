# Dict: release-readiness audit

Date: 2026-11-02
Goal: turn Dict from a personal tool into a public, free, fully on-device dictation app good enough to pull Matt off Aqua Voice.
Constraints: no servers, no paid accounts beyond the existing Apple Developer membership. GitHub (Releases, Pages) is the only hosting.

## 1. What's already strong

The foundation is better than "minimalist" suggests. These are keepers:

- **Engines.** Parakeet TDT v3 via FluidAudio (one-shot decode, ~100x realtime, built-in punctuation) is the forward path and it's good. Apple SpeechAnalyzer is the zero-download fallback with free streaming preview.
- **Capture UX.** Hold-to-talk, toggle, hands-free via Space, Escape to cancel (recording and in-flight processing), 150 ms accidental-tap guard, 250 ms release tail so the last word isn't clipped, edge padding so Parakeet doesn't garble word edges.
- **HUD.** Liquid Glass pill that morphs into a panel for hands-free, live waveform from real audio levels, live transcript with confirmed/tentative styling, success checkmark, Reduce Motion support. This is already close to "wow".
- **Insertion.** Clipboard-preserving paste with nspasteboard transient markers (clipboard managers ignore it), smart leading space via Accessibility, optional trailing space.
- **Formatting.** On-device Foundation Models pass with a verbatim guarantee, word-count sanity check, 15 s timeout, chunking, and a coding-app variant that fixes "get commit" style mishearings. Skipped for Parakeet outside coding apps because Parakeet already punctuates.
- **Plumbing.** Word replacements, SwiftData history with retention, login item via SMAppService, Sparkle wired in, menu bar download progress, ~20 test files with pure logic extracted (DictationKeyLogic, SmartSpacing, LiveTranscript, TranscriptFormatter helpers).
- **Build.** `xcodebuild` passes clean from the command line. The Icon Composer `.icon` bundle is wired as the app icon (the empty `AppIcon.appiconset` is a leftover, not a problem).

## 2. What blocks a public release

Things a stranger would hit in the first ten minutes.

| # | Problem | Where | Fix |
|---|---------|-------|-----|
| B1 | Sparkle can't install updates: no `SUPublicEDKey`, appcast is empty, no signing key generated | project.pbxproj, appcast.xml | Generate EdDSA key, set the build setting, back up the key |
| B2 | No release pipeline. RELEASING.md is a manual Xcode checklist | RELEASING.md | Script: archive, notarize (`notarytool`), DMG, `sign_update`, `generate_appcast`, `gh release create` with real notes |
| B3 | App isn't guaranteed to be in /Applications. Accessibility permission and Sparkle both break when the app is run from Downloads or the DMG | Launch | Offer to move to /Applications on first launch (LetsMove pattern, no dependency needed) |
| B4 | Failures are silent. `lastError` is set but never shown; empty transcripts and engine failures just dismiss the HUD | AppState, HUD | HUD states for "Nothing heard" and "Couldn't transcribe", plus a menu bar hint when the engine isn't ready |
| B5 | Deployment target is 26.4 and versions are inconsistent (Debug 0.1 build 4, Release 1.0 build 1) | project.pbxproj | Set target to the lowest OS the APIs need (likely 26.0), set one version in both configs |
| B6 | Speech Recognition permission is requested even when the engine (Parakeet) doesn't need it | Onboarding | Only ask for permissions the chosen engine needs |
| B7 | No README, LICENSE, privacy statement, or site. Repo is private so release assets can't be downloaded anonymously | Repo | Decide public vs. private (see section 6), add docs either way |
| B8 | 64 `print` calls, no way for a user to send you a log | Everywhere | os.Logger with a "Copy diagnostic log" action in About |
| B9 | Whisper streaming path (StreamingTranscriptionService, SpeechSegmenter, ChunkDecodeQueue, TranscriptAssembler, VoiceGate, TranscriptFilter, ~900 lines + tests) is dead weight and pulls in WhisperKit | Pipeline | Delete it. Two engines (Parakeet, Apple) is a cleaner story |
| B10 | HUD always appears on the main display, not the one the user is typing on | HUDPanelController | Position on the screen containing the focused window or mouse |
| B11 | No microphone picker. AirPods as input silently degrade quality and hijack audio output | Engines | Input device picker with "Prefer built-in mic" default |

## 3. The gap to Aqua Voice

What Aqua does that Dict doesn't, ranked by how much it would matter day to day. These are the differentiators, not the blockers.

1. **Cleanup, not just punctuation.** Dict is strictly verbatim: "um", "like", and "no wait, the charts first" all survive. Aqua removes fillers and applies self-corrections. Proposed: a **Dictation style** setting with Verbatim (today) / Clean (fillers out, self-corrections applied, no rewording) / Polished (light grammar). Implemented with the on-device model plus the existing sanity check, so the raw transcript always wins if the model misbehaves. Rule-based filler removal as a fallback when Apple Intelligence is off.
2. **Context awareness.** Dict knows the frontmost app (coding catalog) but not what's on screen. Via Accessibility we can read the focused field's existing text and hand the formatter the names and terms already present, which fixes most proper-noun misses without a dictionary. Cheap to try, big accuracy win in Slack/Mail/Notes.
3. **Voice commands.** "new line", "new paragraph", "period", "comma", "scratch that". Deterministic post-processing, no model. Small, high-value.
4. **Live words while holding the key.** Live transcript shows only in hands-free. Apple's engine streams for free; Parakeet re-decodes every 700 ms. Showing words as you speak in hold-to-talk too is the single most "alive" feeling thing we can add. Needs care so the preview never delays the final decode.
5. **Custom hotkey.** Four modifier keys only. People will want ⌥Space, a double-tap, or a mouse button. Add a shortcut recorder (sindresorhus/KeyboardShortcuts is MIT) alongside the modifier-only choices.
6. **Sounds.** Subtle start/stop/inserted sounds, with a toggle. Aqua has them; they make hold-to-talk feel confident without looking at the HUD.
7. **Languages.** Parakeet v3 handles 25 European languages; the Apple engine is hard-coded to en-US. Expose a language setting (auto-detect for Parakeet).
8. **Stats.** Words dictated, time saved vs. typing, streak. Every competitor shows this, it's the screenshot people share, and it's free to compute from history.

## 4. Onboarding

Today: one 480x580 screen with three permission rows, an engine picker, and a download row. "Get Started" is disabled until the engine is ready. It works, but there's no moment where the person *feels* it.

Proposed flow (one idea per screen, Continue always enabled where possible):

1. **Welcome.** Icon, one sentence, "Everything stays on your Mac." Move-to-Applications prompt if needed.
2. **Microphone.** Why, then the system prompt.
3. **Accessibility.** Why (global hotkey and inserting text), a short animation of the System Settings toggle, auto-advance when granted (the 5 s poller already exists).
4. **Choose your key.** Visual keyboard, press the key to pick it. Explain hold vs. toggle and the Space trick.
5. **Try it.** A text field in the window. "Hold ⌘ and say anything." Live transcript appears, text lands in the field, checkmark. This is the magic moment and the thing the marketing video shows.
6. **Better accuracy (optional).** "Download Parakeet (500 MB) for the best accuracy. You can keep using Dict while it downloads." Apple engine works immediately; auto-switch to Parakeet when the download finishes.
7. **Done.** Launch at login toggle, where to find settings, one tip.

Default engine decision: Apple for instant start, Parakeet download offered in onboarding and auto-switched on completion. Nobody waits for a download to try the app.

## 5. Settings, history, and the main window

Mostly fine and native. Additions, in priority order:

- General: shortcut recorder, microphone picker, language, dictation style, sounds, HUD position (bottom / near cursor / off).
- History: search, per-entry delete, re-insert into the current app, grouping by day, stats header.
- About: privacy statement ("Zero network requests except model download and update check"), acknowledgments (FluidAudio, Sparkle, Parakeet license, Apple Speech), links, "Copy diagnostic log", "Report a problem" (opens a prefilled GitHub issue or email).
- Menu bar: icon should change while recording and when the engine isn't ready; add "Dictation style" quick switch and "Copy last dictation".

## 6. Distribution with zero running cost

- **Signing and notarization.** Developer ID with the existing team, hardened runtime is already on, notarize with `notarytool`. Free with the developer membership.
- **Downloads.** GitHub Releases hosts the DMG. Requires anonymous access to the repo, so either make `Dict-app` public or create a public releases-only repo. Recommendation: make it public. "Open source, audit it yourself" is the strongest trust signal a privacy-first app can have, GitHub Actions macOS CI becomes free, and Homebrew cask submission becomes possible (`brew install --cask dict`).
- **Updates.** Sparkle feed served from GitHub Pages (same place as the site) rather than raw.githubusercontent, which has caching quirks and is not meant for serving.
- **Site.** One page on GitHub Pages with a custom subdomain (free): hero video of the HUD, "100% on-device", feature grid, FAQ, privacy, download button that always points at the latest release. Static HTML, no framework.
- **Crash reporting.** None that phones home. Users attach a log from About. Honest and on-brand.
- **Name.** "Dict" is hard to search for (Python dict, Dictionary.app). Worth a decision before the site goes up; renaming later costs more. Bundle ID `birchtree.Dict-app` and product name `Dict-app` should become whatever the final name is.

## 7. Proposed roadmap

Each phase ships something usable. Phase 1 is the minimum for a public 1.0.

**Phase 1: Ship-ready foundation (blockers B1-B11)**
Delete Whisper path; logging; versions and deployment target; move-to-Applications; HUD error states; mic picker; active-screen HUD; Sparkle key; release script with notarization and DMG; README, LICENSE, privacy. Decide name and repo visibility first.

**Phase 2: Onboarding and first impression**
New seven-step onboarding with the "Try it" moment; shortcut recorder; sounds; menu bar recording state; auto-switch to Parakeet.

**Phase 3: The accuracy and speed story**
Dictation styles (Verbatim / Clean / Polished); voice commands; screen-context terms for the formatter; live words in hold-to-talk; language setting.

**Phase 4: Delight and the public launch**
Stats; history search and re-insert; marketing site with video; Homebrew cask; first GitHub release with human-written notes.
